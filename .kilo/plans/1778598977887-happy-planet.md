# Teams Module Implementation Plan

## Overview
Standalone module to split participants into teams with admin management UI and real-time updates via WebSocket.

---

## Backend Changes

### 1. New Model: `Team`
**File:** `backend/models/team.go`
```go
type Team struct {
    ID        string    `json:"id" bson:"_id"`
    EventID   string    `json:"eventId" bson:"eventId"`
    Name      string    `json:"name" bson:"name"`
    Color     string    `json:"color" bson:"color"` // hex color for UI
    CreatedAt time.Time `json:"createdAt" bson:"createdAt"`
}
```

### 2. Team Repository
**File:** `backend/database/team_repository.go`
- `CreateTeam(team Team) error`
- `GetTeamsByEvent(eventID string) ([]Team, error)`
- `UpdateTeam(team Team) error`
- `DeleteTeam(teamID string) error`
- `DeleteAllTeamsForEvent(eventID string) error`

### 3. New Handler: Teams
**File:** `backend/handlers/teams.go`
| Endpoint | Method | Auth | Description |
|----------|--------|------|-------------|
| `/events/{eventID}/teams` | GET | Required | List all teams for event |
| `/events/{eventID}/teams` | POST | Required | Create a new team |
| `/events/{eventID}/teams/{teamID}` | PUT | Required | Update team (name, color) |
| `/events/{eventID}/teams/{teamID}` | DELETE | Required | Delete team |
| `/events/{eventID}/teams/assign` | POST | Required | Move participant to team (manual) |
| `/events/{eventID}/teams/auto-assign` | POST | Required | Auto-assign unassigned participants evenly |

### 4. Extend Participant Model
The existing `Participant.TeamID` field already exists. We'll use it. No changes needed to participant model.

### 5. WebSocket: Real-time Team Updates
Extend `quiz_hub.go` to broadcast team changes to admin clients:
- `team:update` - Team list changed
- `participant:assigned` - Participant assigned/moved to team

## Data Flow

### Manual Assignment
1. Admin sees list of unassigned participants
2. Admin clicks participant → selects target team → confirms
3. API call `POST /events/{id}/teams/assign`
4. Backend updates `Participant.TeamID`
5. WebSocket broadcasts `participant:assigned`
6. Admin UI updates in real-time

### Auto Assignment
1. Admin clicks "Auto-assign" button
2. API call `POST /events/{id}/teams/auto-assign`
3. Backend finds all participants with empty `TeamID`
4. Distributes evenly across existing teams (round-robin)
5. Updates all affected `Participant.TeamID` fields
6. WebSocket broadcasts `team:update`

4. **Frontend: TeamsAdminScreen** (admin UI with WebSocket)

6. **Frontend: MyTeamScreen** (user view)
7. **Frontend: Router integration**
8. **Integration testing**

---

## Key Decisions

| Decision | Rationale |
|----------|-----------|
| Team colors stored in DB | Allows consistent display across all clients |
| Auto-assign is server-side | Ensures even distribution, prevents race conditions |
| WebSocket for real-time admin updates | Matches existing architecture (quiz_hub.go) |
| Participant.TeamID already exists | No migration needed for participant model |
| Teams scoped by EventID | Logical separation per event |
